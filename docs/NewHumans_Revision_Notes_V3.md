# NewHumans V3 修改、删除与新增说明

日期：2026-09-15。对照基线：原总设计 V2 与七块开发文档。本说明放在总设计之外，供核对本轮到底改了什么。

## 1. 本次合并结果与优先级

已把《NewHumans_本轮确认设计修改.docx》的 15 项内容和本次消息中的视觉、能量规则并入总设计 V3，并同步七个模块、公共接口和验收要求。现行优先级为：本次最新消息 > 确认附件 > 旧总设计及旧模块说明。

第二种视觉 B / NOETIC OCEAN（无垠认知海）设为 PROVISIONAL_DEFAULT，保留“效果还不够惊艳、需要继续提升”的判断。现有概念图不被写成已经完成的可移动镜头场景或宣传片；本轮不新增美术资产。

知识球继续独立成块，采用状态仍为 UNDECIDED。本轮是设计文档更新，没有替换旧知识球的代码、数据库、页面或部署。

## 2. 修改了什么

| 主题 | 旧设计或原先缺口 | V3 的现行处理 |
| --- | --- | --- |
| 模型与身份 | 更换基础模型或有效权重通常必须建立新 Entity | 模型变成可替换推理引擎；Entity、记忆、目标、关系、权限和钱包保持，路由与实际版本留痕。 |
| 模型可验证程度 | 严格固定模型条件参与判断居民连续性 | 制品保证等级只说明模型来源能否核验，不再决定居民是不是原来的身份；已授权备用模型可以接续。 |
| 知识与个人记忆 | 已有公共认知和记忆索引，但缺少本次确认的统一个人层语义 | 一个公共图，稀疏 Personal Overlay；公共正文不按人或模型复制，个人经历与判断有来源。 |
| 个人判断 | 接触、记住、接受与公共结论容易混用 | 分开 seen、remembers 和 judgment；accepted 若作为接口字段出现，只能由 judgment 派生。 |
| 错误与挑战 | 有公共纠错，但未细化个人挑战处理 | 红色是本人认错；闪烁是待处理挑战。本人坚持或接受纠正后结束对应待办，旧错保留；新的有效挑战可再提示。 |
| 人类代理 | 缺少每人一个主代理及其与本人的明确关系 | 正常 HPA 是本人通信、操作、批量管理入口，共用 Human 的个人层；临时工作状态和执行来源单独标记。 |
| 人类意志 | 自动代理写知识时可能混淆谁作出的决定 | 最终接受、坚持、认错须本人对具体对象、证据和结论作确认；代理只检索整理，不能静默替本人判断。 |
| Energy 定位 | 主要称为可转移资源额度 | 明确为默认官方货币 E，任务、服务和多数内部交易以 E 结算；现实成本账继续独立。 |
| 运行资格 | 主要检查是否能承担付费调用 | 增加首次至少 100 E、活动日费 1 E、可用 E ≤0 不新增活动、低于 100 E 不主动寻找任务；token 另计。 |
| 休眠和邀请 | 无资金暂停，但免费投递和代理运行边界未完整展开 | 全天休眠不收日费，不启动新推理；系统可代收邀请。零余额不能免费议价，补资并满足资格后才能协商。 |
| 出生与继承 | 出生、克隆和后代为主 | 加入 HPA 失联 2 年寻找、随后 3 年未验证或正式确认死亡后的觉醒资格、独立身份与虚拟权益继承。 |
| 模块分工 | 总设计和分块表存在局部职责口径不同 | 统一七模块数据所有权，日费归 M05、运行归 M02、身份与本人验证归 M01；跨模块事务有明确边界。 |
| 预算和阶段验收 | 旧预算没有固定活动日费及 HPA 计费实例 | 日费与 token 成本分列；两名人类的 HPA 另按实际活动日计算；补齐新规则的验收场景。 |
| 视觉默认 | 三个风格候选待选择 | 暂定第二种 B，补入调色、构件尺度、材质、镜头和新模块对齐要求，知识状态颜色仍遵循认知语义。 |

附件第 2 项用“接触、记住或接受”概述点亮，第 4.1 项更具体地将正常点亮定义为“当前接受”。合并时以第 4.1 项的视觉表统一状态，接触和记住保留为独立属性，避免把 HPA 读过材料伪装成本人已经认同。

## 3. 删除或废止了什么

这里的“删除”指从现行规范中撤下冲突条款，不是删除原附件、旧版本历史或生产数据。

1. 废止“更换基础模型、LoRA、微调或量化变体必须创建新身份”的规则；独立克隆、后代和 HPA 觉醒才按新主体处理。
2. 撤下“接入不同模型只能建立继承者”“只能由原固定主体模型作重要决策”等要求，改为获授权路由、统一上下文和单一权威提交分支。
3. 替换将模型制品不可核验等同于居民身份不连续的验收口径；模型来源真实性检查本身保留。
4. 替换仅把 Energy 定义成资源额度的现行表述，改为官方货币，同时保留真实费用、精确金额、预留、托管、发行依据与对账。
5. 撤下与最新规则不兼容的活动资格表述，例如只要有人代付 token 就能继续活动的潜在解释；正 Energy 与日费资格仍必须满足。
6. 把“归档费用待定”改为“公共归档预算与保存政策待定”，避免后续借归档费暗扣休眠主体。

个人知识球本版明确不设置黄色“长期不确定”状态；这是对新状态语义的补充约束，不声称旧 V2 曾经定义了一个黄色状态然后被逐字删除。公共证据不足、公共争议仍保留。

## 4. 添加了什么

- 人类密码学身份根、唯一 HPA 绑定、本人直接/代理自动/本人确认三种行动来源，以及本人具体确认的有效期、版本和防重用要求。
- 统一 Context Builder、模型路由变更流程、旧请求迟到处理、共享个人层与觉醒后只读初始快照。
- PersonalNodeState、个人状态修订、个人挑战待办与纠正关系；公共审核和个人决定分别提交，多个待办分别关闭。
- 批量通信的逐项请求、总预算、超时、部分完成、来源追踪、分歧保留与同源去重。
- RecoveryProfile、SuccessionPolicy、两年/后三年状态机、搜索预算、正式验证、死亡复核、资金或渠道不足及主人回归竞态。
- 虚拟继承的资产与权利清单。管理别的 Agent 不等于拥有其自有财产；继承本人公司权益不等于取得整个公司。主人后来回归也不删除已经独立的新主体。
- 日费记录、激活记录、余额门槛、资金冻结口径、原子扣费与动作复查、HPA 专用预算、同日去重和跨日处理。
- 远期知识容量估计与工程口径说明。50—100 TB / 1 万亿节点仅约 50—100 字节/节点，不能容纳完整来源、向量、历史和索引；完整工程库须另外采样估算。
- nh.v3.0 接口合同与兼容要求，旧事件按原版本解释，旧有不同 Entity 不自动合并。
- 18 项 V3 专项验收要求（V301—V318）与 10 项新增知识球验收要求（KB27—KB36）。这些是未来实现须验证的场景，本轮没有运行完整系统。
- 独立的机器可读默认参数 NewHumans_Energy_Policy_V3.json，状态明确标为 DESIGN_DEFAULT_NOT_IMPLEMENTED。

## 6. 为了能实施而补上的默认选择

下表均为本轮补齐的实现默认值或边界解释，不冒充你逐字指定过的内容。以后可以按正式规则版本调整。

| 默认选择 | 具体含义与影响 |
| --- | --- |
| UTC 自然日计费 | 不是滚动 24 小时；跨过 UTC 零点继续活动进入新计费日，因此零点前后短时活动也可能涉及两个日费。 |
| 首次按 ≥100 解释 | 界面默认拨入 100；首次成功扣 1 后为 99，不能主动寻找任务。 |
| 门槛使用可用余额 | 已入账钱包减未结预留和不重叠冻结；未释放托管、口头报酬和未来代付额度不算可用资金。 |
| 先结日费，再判资格 | 未付本日费且余额 ≤1 E 时不扣成零，直接等待补资，不形成日费欠账。 |
| 唤醒不重复首次门槛 | 已成功激活的主体以后无需每次恢复都达到 100，但仍须有正余额并支付本日未付日费。 |
| 同日收费一次 | 模型切换、重启、迁机、多个线程和窗口不叠加日费；当天已活动后休眠不按小时退日费。 |
| ACTIVE 与 DORMANT 分开 | 启用但空闲或等待仍是 ACTIVE；真正休眠才停止后续计费。关闭网页不等于休眠。 |
| HPA 计费范围 | 激活 HPA 默认也算一个运行主体，日费从主人持有的专用代理预算支付；人类账户本身不再另收一份日费。 |
| 零余额只代收邀请 | 系统不调用 Agent 免费议价；资助者可先转入真实资金，唤醒后 Agent 仍需确认合同。 |
| 限制的是主动找任务 | 低于 100 不禁止所有自主研究、艺术、非招揽社交和既有合同履行；这些活动仍需正余额与预算。 |
| 日费进入消费核销 | 沿用旧资源消费账的核销方式，日费退出流通，不同时又成为平台可花余额；内部交易只转移 E。 |
| 两年/后三年用日历周年 | UTC 周年；闰日到不存在该日期的年份时取 2 月 28 日。后三年从逻辑上的 Recovery 到期点起算。 |
| 失联计时的可信起点 | 新账户以建身份时的本人验证初始化；旧数据时间未知先核验，不能把空值当成年代久远而直接继承。 |
| Recovery 实际行动收费 | 系统计时不要求 HPA 天天活动；真正寻找、联系、推理仍有日费与实际成本。没有资金或渠道时明确阻塞，不伪造已经找过。 |
| 觉醒资格与激活分开 | 符合条件后创建新身份并核对虚拟权益；新主体资金不足 100 时先登记为未激活。 |
| 闪烁的无动画表达 | 减少动态效果时用持续的待判断图标和计数表达同一事件，关闭动画不等于挑战已解决。 |

同一个已获授权动作复查时，可加回仅为它尚未耗用的专属预留；这是核验原有授权资金，不是允许零资金居民无限调用。额外动作不能借用该预留，整个持续人生也不能包装成一个永不结束的 action。

三个容易忽略的例子：

1. 首次 100 E → 日费 1 E → 99 E：只能被动获取任务；收到邀请后仍需预算来协商。
2. 首次 101 E → 日费后 100 E：此刻有主动寻找资格；若规划 token 自付 0.2 E，随后为 99.8 E，下一主动寻找动作会被拒绝。
3. 之前已激活、当前 0 E → 资助 2 E → 若本日未付费则剩 1 E：可以在预算内醒来协商，但不自动签约。若是从未激活的新主体，2 E 仍不够首次门槛。
