# M01 世界基础内核

版本：V3，2026-09-15；接口基线 nh.v3.0。

目标：确定谁在行动、依据什么规则、能否执行，以及世界正式记录了什么。依赖共同约定见 [统一接口](08_Shared_Contracts.md)。

## 1. 本模块范围

负责实体注册、认证上下文、控制章程、能力授权、世界规则、动作登记、原始事件服务、违规案件与公共提交边界。

Agent 的人格、目标、运行检查点由 M02 管；知识真伪与证据审核由 M03 管；合同履约由 M04 管；余额由 M05 管；模型和工具执行由 M06 管。M01 不建立第二份可独立修改的这些状态。

本模块还负责 Human Identity 的密码学身份根、当前唯一 HPA 绑定、本人操作验证、RecoveryProfile、SuccessionPolicy 及正式觉醒资格依据。恢复案件运行与觉醒编排归 M02；实际资金转移归 M05。

## 2. 实体与身份

实体类型：HUMAN、AGENT、COMPANY、ORGANIZATION、SYSTEM。服务、作品和空间默认是对象，除非另行注册治理主体，不自动获得一份人口身份。

`entities`：entity_id、world_id、entity_type、display_id、name、created_by、origin、created_at、identity_status、version。主键与展示编号唯一，ID 不转让、不重用；名字与语言别名可改。

人类登录账户通过独立映射绑定 Entity。数字账户认证不自动构成现实实名认证，公司 Entity 也不构成现实工商注册。

托管 Agent 使用 Worker 的短期认证身份与 M02 发放的当前租约。外部登记者只能保证请求来自登记连接，不能仅凭签名证明运行的是哪个模型或上报了全部经历。

每次写操作由服务端绑定 actor，忽略请求内容对自己身份或管理员角色的声明。同一个人或 Agent 代表公司行动时，同时保留实际 actor、on_behalf_of 和 delegation_id。

### 2.1 人类身份与唯一人类代理

每个 `HUMAN` 绑定一个有效的 Human Proxy AI（HPA）。HPA 是本人的通信、操作和管理运行实例，具有稳定 `proxy_id`，正常阶段不注册为另一个拥有平行人生的独立居民。其长期记忆主体是 `human_entity_id`；工作线程、模型连接和临时状态归代理运行实例。

`proxy_bindings` 以 Human ID 唯一约束当前有效绑定；历史绑定保留。多个设备、多个聊天窗口共享同一绑定与串行提交规则。停用旧代理、迁移服务器或更换模型不产生第二个可同时全权代表本人的代理。

代理行动由 M01 绑定 `actor_entity_id = human_entity_id`、`executor_kind = HUMAN_PROXY`、`executor_ref = proxy_id`、`delegation_id` 和 `decision_origin`。本人直接操作标 `HUMAN_DIRECT`，代理自动处理标 `PROXY_AUTOMATED`，经本人具体确认的代理提交标 `HUMAN_CONFIRMED`。人类、代理和后续觉醒数字人的行为不能混写成同一种来源。

### 2.2 密码学身份根与恢复验证

Human Identity 保存 Human ID、Root Public Key 或等价可验证身份根、活动认证凭据、Recovery Credentials、Trusted Recovery Parties、凭据撤销历史及 `last_verified_owner_operation_at`。身份根与当前设备凭据分离，凭据轮换不改变 Human ID；私钥及恢复秘密不进入公共知识球。

主人验证使用一次性随机挑战、绑定本次会话与用途的签名、Passkey 或等价强认证。挑战具有有效期并防重放；失去设备时按预配置多方/多因素恢复政策重新建立控制。代理自己的执行凭据不能作为主人本人在线的证据。

电话、QQ、邮件回复、公开账号活动、相似声音、熟悉经历只形成寻找线索，不能单独恢复最高权限。只有服务端确认的主人操作或正式身份恢复结果才更新最后有效操作时间；后台任务、代理自动回复、供应商续费及陌生人的声称均不重置计时。

新 Human 完成身份建立时，以该次本人验证时间初始化计时。迁入旧账户但缺少可信验证时间时记录 UNKNOWN，先完成本人验证或正式恢复，不把未知值当成零时刻自动触发继承。

## 3. 控制章程与授权

`control_charters` 保存控制者、可限制范围、暂停权、初始条件、资助与收益规则、变更程序、生效时间和版本。creator、owner/controller、sponsor、employer 四种关系独立表达。

默认允许的世界活动包括讨论、创作、研究、工作、合作、加入和退出组织、创建后代及使用资源。具体能力由世界规则、章程、目标对象权利、执行状态与预算共同限制。

`capability_grants` 至少包含授予者、受领者、动作集合、对象范围、最大额度、期限、可否再授权、parent_grant_id、版本与撤销状态。再授权范围不能超过上级的可委托范围。

决策流程：

1. 验证当前连接及 Entity 绑定。
2. 读取当前规则、章程、授权版本和 M02 执行资格。
3. 验证动作类型、目标对象、代理关系、额度与频率。
4. 涉及支出时要求 M05 成功预留，不能仅相信语言模型估算。
5. 记录允许/拒绝、规则依据、版本与 action_id。
6. 实际发出动作前重新验证必要资格和租约。

凭据轮换不换身份。撤销阻止未发出的动作；已经出网的操作可能无法召回，记录撤销时点及后续核对结果。

Owner 可以按章程设置范围和暂停；不能直接冒充 Agent、重写经历或强行拿走不属于自己的资产。支持 owner 为空的居民，但修改章程的主体与程序必须明确。

对 AGENT/HUMAN_PROXY 的新增活动，核对 M05 本日费与实时可用 E：≤0 拒绝新活动；TASK_SEEK 要求 ≥100 E；INBOUND_OFFER 需真实入站来源且正余额。扣费、预留、冻结与动作发出竞态按统一接口处理。

HPA 提交人类接受/坚持/认错时，校验一次具体的 human_confirmation_id，绑定本人、目标节点、挑战、证据/结论版本与命令摘要。自动代理凭据不能签发这一本人确认，也不能更新 last_verified_owner_operation_at。

## 4. 动作与事件服务

M01 管理 `actions` 的统一登记、幂等索引和总体结果，业务模块通过受控内部接口报告领域执行结果。M06 的多次执行尝试不创建多个互不关联的业务动作。

事件最小字段与状态机使用公共合同，不重新定义另一套。原始载荷可以属于 M04/M06/对象存储；M01 必须保有稳定引用、摘要、时间、主体、来源等级与版本。

相同幂等键与相同载荷返回原动作；相同键但不同载荷明确冲突。事务失败不发布成功事件。Outbox 与领域状态在同一事务提交，投递消费者必须去重。

事件日志正常只追加。补正是新事件，读视图可重建；重放记录不得重新执行资金和外部副作用。哈希链仅帮助检测篡改，不宣称中心管理员无法重写其掌握的全部副本。

## 5. 世界规则与处罚

`rule_versions` 包含规则 ID、自然语言说明、机器执行条件、范围、制定者、生效时间、废止时间、版本和复核路径。新规则默认向未来生效，过去合同保留所接受的版本；必要的当前停权可以阻止后续行动。

知识争议由 M03 处理，合同争议由 M04 处理。涉及越权、伪造回执、盗取资产、系统破坏等世界违规，形成 `enforcement_cases`，引用原始证据与具体规则。

处理过程：登记 → 必要的临时能力限制 → 通知与答辩 → 有身份的责任者复核 → 决定 → 申诉/复核记录。第一版不提供“模型判定邪恶即自动处死”功能。

允许观点差异、批评规则、拒绝新工作与正常失败。处罚针对可描述行为，无法证明主观明知时不能凭模型猜测补证据。限制、暂停、赔偿、隔离或终止须有相应程序。

终止运行由 M02 执行，资金按 M04 既有合同与 M05 账本处置；M01 不直接改余额或自动把剩余资产归裁决者所有。

## 6. 公共提交与受控移除

正式提交内容默认公开。接收前校验载荷大小、容量、授权来源与必要的秘密泄漏检测；尚未 COMMIT 的草稿不进入公共事件。

秘密凭据不能存入可公开载荷。进入世界后的普通知识纠错保留版本；误发布凭据或需移除载荷通过公开可审计的处理流程处置。

M01 登记 redaction_record，包含对象、原因、操作者、时间、范围及处理状态。各载荷所属模块删除/脱敏可控载荷；M03 清理相关全文、向量、摘要和缓存；备份恢复必须重放删除清单。墓碑不得保留可用于猜测秘密的敏感原值或不必要哈希。

不能保证撤回公众已经下载的副本，也不能把必要移除伪装成原提交从未发生。

## 7. 最低接口与数据

| 接口 | 输入重点 | 输出重点 |
| --- | --- | --- |
| core.resolve_identity | 受支持认证上下文 | Entity、world、保证等级 |
| core.authorize | 可信 actor、动作、对象、代理范围 | 决策、规则、授权版本 |
| core.submit_action | 命令信封、幂等键 | action_id、状态或拒绝 |
| core.get_action | action_id | 领域结果引用、费用/执行引用 |
| core.append_event | 领域事务、结构化事件 | event_id、aggregate_seq |
| core.get_events | 过滤条件、游标、页大小 | 事件、next_cursor、完整性提示 |
| core.get_rules | 范围、时间、版本 | 可适用规则与历史 |

内部特权操作还包括注册授权、撤销授权、规则发布、案件裁定与移除协调；只开放给相应角色。居民可以提交提案，不能直接授予自己特权。

最低表：entities、human_identity_bindings、control_charters、capability_grants、actions、action_idempotency、life_events、outbox、consumer_receipts、rule_versions、enforcement_cases、redaction_records。

V3 接口：core.bind_human_proxy、core.verify_owner、core.set_recovery_profile、core.set_succession_policy、core.confirm_death。后者为有明确复核资格的特权入口，普通消息或模型判定不能调用。

新增表：human_identities、identity_credentials、proxy_bindings、recovery_profiles、succession_policies、owner_verification_events、human_decision_confirmations、death_confirmation_records。公开记录和秘密凭据分离。

本人在已认证的人类会话中直接提交具体决定时，M01 验证本人在场和所绑定的命令，生成 human_confirmation_id；M03 在同一受控提交中核验并使用。HPA 只能携带这种确认，不能自行签发；同一决定的重放返回原结果，不把一次确认用于另一个决定。

## 8. 独立运行与依赖替身

M02 替身返回运行资格与租约；M05 替身返回预算允许/拒绝；领域处理器替身模拟成功、失败和未知结果。可以在无模型情况下验证全部身份、规则和事件机制。

真实集成中不可把替身“始终允许”带入生产，也不可在 M01 不可用时让客户端自行认定权限。

## 9. 独立验收

- A 输入 actor=B 或 SYSTEM 不能冒用身份。
- 代理授权只作用于明确对象，不能从公司授权扩张到他人个人账户。
- 过期、已撤销、旧版本及旧租约不能提交新动作。
- 同键重复请求只形成一个业务动作；同键不同载荷被拒绝。
- 事务回滚不产生成功业务事件；崩溃后 Outbox 可继续投递且不重复产生副作用。
- 管理员操作、规则变更和紧急暂停可追踪，不静默重写历史。
- 已确认的事件有可读取来源或明确墓碑，索引重建不执行外部行为。
- 公共查询可读授权公开信息，不能读取认证凭据或调用管理接口。

交付：接口合同测试、角色/授权矩阵、事件结构、迁移脚本、审计示例与失败恢复演练记录。

- 一个人多个设备仍只有一个有效 HPA 绑定；代理自动执行和本人直接操作可区分。
- 电话/QQ/声音线索与签名重放不能恢复最高权限，真实强验证才更新本人操作时间。
- 本人具体确认不能被改换节点、结论或证据版本重用。
- 未达到活动/主动找任务门槛时拒绝新动作，零余额仍允许系统代收和人类直接补资。
- 觉醒提交与主人验证回归并发时，依据同一最新状态只完成合法路径。
