# M03 知识球独立开发规范

版本：V3 模块版，2026-09-15。  
采用状态：**UNDECIDED；是否替换旧知识球由项目所有者决定。**

本文件可以单独交给开发者，用于制作、测试和评估知识球。它覆盖独立知识产品与接入 NewHumans 两种形态。世界集成时再遵守 [统一接口](08_Shared_Contracts.md)。

## 1. 产品目标与范围

知识球提供一套长期可维护的公共认知系统：保存输入与出处，抽取可区分的命题，识别已有知识，关联新证据，处理冲突和错误，维护公开信念与个体召回索引，并让人和 Agent 查询或编辑。

知识球不要求先存在 Agent 社会。一个人也能提交材料、建立知识、查阅证据、提出异议并使用 3D 展示。接入世界后，同一引擎再处理居民的消息、行为和经历。

### 1.1 三个独立交付部分

| 部分 | 内容 | 替换边界 |
| --- | --- | --- |
| M03-A 认知引擎 | 存储、命题、断言、来源、证据、查重、推导、审核、记忆、检索 | 可在不重做 3D 界面的前提下升级 |
| M03-B 展示与编辑 | 3D 球体/2D 视图、节点、连线、详情、证据、争议、编辑入口 | 旧展示可通过兼容接口继续使用 |
| M03-C 接入与兼容 | 独立用户、NewHumans 事件、旧数据与旧接口适配 | 隔离外部系统差异，不污染认知模型 |

### 1.2 不归知识球决定的事项

身份是否有权代表某人、真实余额、权限授予、合同生效、公司成员资格、Agent 当前运行状态与模型调用版本，均由相应权威系统决定。

知识球可以检索这些事实的记录，也可以保存对它们的解释与质疑；不能通过“接受一个命题”修改世界余额、取得管理员权限或解除运行暂停。

V3 以“一个公共知识图 + 每个主体的稀疏 Personal Overlay”为基础。知识基本单位是语义去重后的最小可复用节点；原始文件、逐笔观测和临时推理不按其数量自动计为永久知识节点。语言/措辞/来源不同但语义等价时复用 canonical 节点，保留各来源和证据。

模型是可替换引擎，同一 Entity 的个人层与记忆不随模型切换分裂。HPA 正常阶段使用主人的个人层，觉醒后才有独立数字主体自己的个人层。

## 2. 独立模式与世界模式

| 基础能力 | 独立知识球 | 接入 NewHumans |
| --- | --- | --- |
| 身份与授权 | 自己的认证适配器和本地角色 | M01 的 Entity 与授权 |
| 来源和正式提交 | 知识球自己的 source/event 服务 | 复用 M01 原始事件；新增提交也登记世界事件 |
| 模型抽取与比对 | 自己配置的模型适配器、调用配额及付款者 | M06 提供能力，M05 提供预算 |
| 认知数据库 | 独立认知表与对象存储 | 同一逻辑模型，可共享部署、保持写入归属 |
| 个人记忆 | 用户/外部主体的 Personal Overlay 与公开关联 | Agent/Human 的个人层；正常 HPA 绑定 Human ID |
| 展示 | 独立知识球页面 | M07 嵌入 M03-B，或跳转独立页面 |

独立模式不需要虚拟货币、公司或任务市场；仍需持久化、认证、资源配额和真实费用承担者。测试用虚拟模型或无鉴权本地演示只能用于隔离环境。

独立知识球不因接入人类代理功能而必须部署完整世界。IdentityPort 提供本人确认验证；在没有 HPA 的独立产品中由认证用户直接作判断。NewHumans 内 Agent/HPA 的运行日费与 0/100 门槛由世界的 M01/M02/M05 执行，不把独立人类直接查知识强行变成 Agent 首次激活。

## 3. 不能破坏的认知约束

1. 原始陈述存在，不代表陈述内容为真。
2. 新命题不代表正确命题；已有命题不代表永远正确。
3. 语义相似不等于完全等价；没有检索到不等于不存在。
4. 对同一来源的重复引用不增加独立证据数量。
5. 保留否定、量词、条件、时间、地点、单位和不确定性。
6. 一个候选可同时与不同旧命题重复、冲突或有推导关系。
7. 当前审核结论可被挑战；历史修正、误合并与派生失效可追溯。
8. 个体记忆公开但召回参数按主体区分；A 的遗忘不改变 B 的记忆。
9. 已确认提交必须有持久来源记录；未完成处理不得声称没有新知识。
10. 凭据、系统命令和认证信息不因出现在公开文本中就获得执行权。

11. 正常 HPA 不拥有平行长期人生，不得在没有本人具体确认时改写主人的个人接受/认错状态。
12. 个人错误保留；挑战闪烁是未完成判断事件，没有黄色“长期不确定”个人状态。
13. 公共证据判断与个人接受分开，个人坚持不能改写公共审核。

## 4. 概念与类型

| 类型 | 示例 | 语义 |
| --- | --- | --- |
| SOURCE / EVENT | 一条发言、一份数据、一份工具回执 | 输入来源与发生记录 |
| KERNEL_FACT_REFERENCE | 内部转账成功的事件引用 | 只读引用权威系统事实，不允许居民伪造来源等级 |
| CLAIM | 某种方法在某条件下有效 | 可检验或可争议命题 |
| BELIEF | A 公开声明相信命题 P | 归属 A 的立场，不直接证明 P |
| PREDICTION | 指定日期指标超过阈值 | 带观测口径和检验期限 |
| PREFERENCE / VALUE | A 喜欢研究数学 | 偏好或价值立场，不强行当经验事实投票 |
| GOAL_REFERENCE | A 声明想完成一项作品 | 目标的引用与历史；当前目标权威状态在 M02 |
| NORM_REFERENCE | 某规则版本允许某动作 | 规则出处与适用范围，不自行赋权 |
| ARTIFACT_REFERENCE | 代码、图像、论文、数据集 | 制品版本、来源、贡献和许可 |

引用权威事实与对该事实的解释分开。来源核验失败时只能保存“某人提交了这一说法”，不能生成受内核认证的事实。

问句、指令、假设、小说内容和比喻要保留类型或 context。问“P 是否成立”不等于声明 P；“如果 P 则 Q”不能直接拆成 P 与 Q 都成立。

## 5. 原始来源与提交协议

`SourceRecord` 至少包含：source_id、world/namespace、提交者、原始语言、内容/载荷引用、内容摘要、发生时间、记录时间、来源类型、外部出处、上游 source_id、公开范围和版本。

提交时：

1. 认证提交者，核对世界或独立模式的授权。
2. 明示提交后公开；检查载荷大小、持久化容量与处理预算。
3. 排查明显凭据泄漏；不把秘密原值传入公共知识或普通日志。
4. 原始内容持久化，产生 source_id；世界模式关联同一份 M01 event_id。
5. 返回 source_id、处理任务 ID、已保存状态与预期处理方式。
6. 异步执行抽取；过程失败不能删除已经确认的来源。

模型抽取失败时原文仍可读，并可在预算恢复后继续。内容超过输入限制时在提交前明确拒绝或让调用方分块；不返回成功后悄悄截掉后半段。

来源正文存对象存储时，先完成可核验载荷写入，再提交元数据引用；未被引用的暂存对象可清理。不能让元数据成功但实际载荷尚未保存。

## 6. 命题、断言与时间

### 6.1 Claim：规范化命题结构

```json
{
  "claim_id": "claim-1",
  "schema_version": "nh.v3.0",
  "predicate_version": "performs_work_for.v1",
  "subject_ref": "entity-a",
  "predicate_id": "performs_work_for",
  "object": {"kind": "entity", "ref": "entity-rushow"},
  "polarity": "POSITIVE",
  "quantifier": "INDIVIDUAL",
  "modality": "ASSERTED",
  "qualifiers": {},
  "canonical_hash": "digest-example"
}
```

对象值必须区分实体引用、文字、数值、日期、集合等类型。数值必须有单位，金额必须有币种或资产类型；时区和地域可作为限定条件。

canonical_hash 来自规范序列化的完整语义结构：实体、谓词及版本、对象、否定、量词、模态、限定条件。作者、插入时间、召回次数和自报置信不进入命题结构键。哈希相同还核对完整规范内容，避免把哈希碰撞当语义证明。

英文作为机器字段和规范谓词的默认语言；输入原文与可选译文保留。机器 ID 不依赖中文或英文显示名。

### 6.2 Assertion：语境与有效期间中的断言

```json
{
  "assertion_id": "assertion-1",
  "claim_id": "claim-1",
  "world_id": "world-1",
  "context_ref": "real-world-statement",
  "valid_from": null,
  "valid_to": null,
  "valid_time_known": false,
  "valid_time_precision": "UNKNOWN",
  "recorded_at": "2026-09-14T12:00:00Z",
  "source_refs": [{"source_id": "source-1", "span_id": "span-1"}],
  "review_status": "PROPOSED",
  "epistemic_status": "INSUFFICIENT_EVIDENCE",
  "derivation_kind": "DIRECT"
}
```

同一规范命题可以对应多个语境、有效期间与证据记录。不同日期的独立事件不能只因三元组相同而合并为同一个发生事件。

完全一致的断言范围可以复用断言并追加 evidence；无法确定两次说法是否涉及同一期间时保留待判定关系，不用未知时间伪装成无限有效区间。

### 6.3 双时间

有效时间表示信息说的是什么时候；记录时间表示系统什么时候知道。已知有效区间用 `[from, to)`，未知起点、未知终点和恒定定义明确区分。

9 月 20 日才知道某关系于 9 月 10 日结束：追加修正，保留原断言及之前系统的认知状态。查询支持“截至某时已知的信息”和“按当前证据看某时的情况”，不把两者混为一谈。

### 6.4 严格例句

输入：“我是 Agent001，我在给老板 Rushow 干活。”

- 发言身份由认证绑定，文本不能改变 actor。
- 工作关系先作为带来源的自述命题，时间未知则明确未知。
- 不自动推导正式雇佣合同、管理权、所有权或资金归属。
- 只有 schema 明确规定互逆的谓词才能生成反向视图。
- 同时为 B 和 C 工作，在没有排他规则时并不矛盾。

## 7. 抽取与写入流水线

1. 保真来源，登记处理器版本、预算和 source_id。
2. 识别事实、自述、信念、预测、偏好、目标、规范、问题等类型。
3. 按完整语义原子化，保留来源片段，不拆掉条件。
4. 实体消歧；同名实体使用 ID，歧义保留候选。
5. 按版本化词表规范化谓词、单位、时间和限定条件。
6. 精确键、实体/时间索引、全文、向量依次召回候选。
7. 分别比较等价、蕴涵、矛盾、新颖性与不确定性。
8. 检查证据根与独立观察，避免重复增加支持数量。
9. 复用已有节点、创建提案、登记推导或发起挑战。
10. 更新处理覆盖、审核队列、索引与必要的派生失效通知。

处理任务字段：job_id、source_id、processor_version、chunk_cursor、covered_spans、pending_spans、candidate_ids、budget、status、retry_count、error、updated_at。

状态为 PENDING、PROCESSING、DEFERRED、COMPLETED、FAILED。COMPLETED 只表示预定范围处理完成，不表示穷尽所有可能的隐含推论。

初值每批最多 64 个候选，超出后分批 DEFERRED。目标是保存来源并尽量完整抽取显式命题与有界直接推论，不无限枚举可联想到的所有结论。

同一源事件、处理器版本与分块键幂等。索引完成、抽取完成、同一派生回写等内部通知不再次抽取自己，避免递归产生无限记录。重跑新处理器版本可以提出新结果，但仍经过全局命题和证据去重。

## 8. 等价、冲突与新颖性

结果采用多关系集合：

```json
{
  "candidate_id": "candidate-17",
  "equivalent_to": ["claim-4"],
  "entailed_by": [],
  "conflicts_with": ["claim-9"],
  "novelty": "EXISTING",
  "needs_review": true,
  "comparison_version": "compare.v2"
}
```

novelty 为 EXISTING、POSSIBLY_NEW 或 UNDETERMINED。即使复用 claim-4，仍登记与 claim-9 的冲突；不得查到重复就提前退出。

### 8.1 完全重复

完全相同规范结构由数据库唯一约束挡住并发重复创建。将来源关联到已有命题；只有新的独立测量/材料才增加 evidence，不因反复插入同一来源增权。

### 8.2 语义等价

全文和向量只是召回手段。时间、量词、否定、条件和实体不同不得自动合并。LLM 的等价意见先形成有来源的比较结果；不确定项保持 POSSIBLE_EQUIVALENT。

确认等价使用可撤销映射，保留旧 ID、出处和所有审查历史；错误等价可拆开，重新构建受影响视图和派生。

### 8.3 蕴涵

自动认定 RULE_DERIVED 必须提供有效前提 assertion_id、规则 ID/版本、适用范围、生成器版本和核对结果。第一版只支持登记过的有限规则，例如明确互逆关系和范围保持的简单推导。

模型给出的自然语言“可推出”登记为 MODEL_INFERRED 提案，不冒充形式证明。前提失效后标记派生过期，重新验证；循环论证不能作为证明。

社会关系允许环，证明依赖按推导实例无环。存在相反命题时隔离争议，不能由矛盾推出任意结论。

### 8.4 潜在冲突

先匹配实体、谓词语义、世界、条件与重叠时间，再判断正反、互斥或数值约束。不同有效期、不同测量口径或非排他关系不能仅因对象不同判矛盾。

冲突首先产生需要核查的关联，展示双方证据；新证据可以修正旧结论，也可以被旧证据反驳。模型无法决定时保留争议或证据不足。

### 8.5 开放世界

没有找到 P 不代表非 P，没有找到重复也不证明全世界绝对新颖。第一版不承诺任意自然语言的完全查重、完备推理与自动真理判断；应报告各类误差和待审比例。

## 9. 审核、证据与纠错

### 9.1 三个状态维度

| 维度 | 状态 |
| --- | --- |
| review_status | PROPOSED、UNDER_REVIEW、ACCEPTED、REJECTED |
| epistemic_status | SUPPORTED、CONTESTED、INSUFFICIENT_EVIDENCE、REFUTED、SUPERSEDED |
| derivation_kind | DIRECT、RULE_DERIVED、MODEL_INFERRED |

ACCEPTED 表示在指定规则下当前接受，仍可以被挑战。DERIVED 表示来源，不等于正确。SUPERSEDED 表示版本被替代，REFUTED 表示被现有证据反驳。

审核状态变动保存 review_id、审核者、角色、政策版本、依据、时间、前后状态。居民可以提出、支持、反驳、挑战和提交证据；审核状态由有相应资格的验证器或复核者变更。

重新打开旧案需有理由/新证据，保留原案及原裁定，不重新制造一个无关联“首次提案”。

### 9.2 证据结构与独立性

Evidence 包括 evidence_id、assertion_id、source_id、root_source_id、observation_id、method、support_or_refute、observed_at、source_span、artifact_digest、upstream_refs、submitted_by 与 dedup_key。

同一文章被 100 个主体引用属于共享来源；转述链和共同数据源可追踪。同一模型的多次赞同不自动构成多份独立验证。关联控制者、模型和提示可作为相关性线索，不能保证揭示全部串谋关系。

展示原始证据数、独立来源根数、证据类型、相反证据与复现结果。单一置信评分未校准前，禁止解释成真实概率；可以为空或明确标记为未校准评分。

### 9.3 不同类型的验证器

| 内容 | 验证方式 |
| --- | --- |
| 权威业务引用 | 向相应权威接口核对，不用投票决定转账是否发生 |
| 代码、计算结果 | 固定版本、输入、运行环境和测试，记录可复现范围 |
| 外部事实 | 检查原始观察、来源、时间、口径和独立证据 |
| 自述技能 | 保存自述，另关联真实测试和交付结果 |
| 信念、偏好 | 核验声明主体和时间，不证明被相信的命题为真 |
| 预测 | 预先确定目标、阈值、期限与数据源，到期核对 |
| 价值立场 | 保留理由和异议，不把人数变成经验事实证明 |
| 世界规范 | 保存授权发布的版本与适用范围，不由认知投票直接赋权 |

### 9.4 挑战结果

挑战包含目标断言、异议类型、同范围说明、证据、请求结果和相关旧案。结果可为维持、反驳、限制范围、纠正有效期、拆歧义或保持争议。

重复无新证据挑战关联原案，受配额约束。提出异议不自动扣被质疑者的资金。第一版公共复核由明确角色与有限预算负责，模型评审意见只是过程的一部分。

不按节点数量、投票次数和互相支持次数发放无限奖励。若设奖励，必须来自明确有限预算并基于可验证贡献，独立于“接受该命题”的真实性判断。

个人挑战的处理不等于结束公共审核案件。一个公共 ChallengeEvent 可以对应多个主体各自独立的 PersonalChallengeReview，某主体完成判断不替别人完成。

## 10. 个人知识球与统一个人记忆

### 10.1 一个公共知识图与稀疏 Personal Overlay

每个人类和独立数字主体的个人知识球，都是同一公共 Knowledge Ball 上的个人状态层，不复制节点正文、来源或整份世界知识库。`PersonalNodeState` 以 `(subject_id, node_id)` 唯一，个人记忆以 `(subject_id, item_ref, relation_kind)` 关联现有公共节点或事件。

个人层记录接触、记住、当前接受、曾接受后认错、自行提出、经历关联、召回参数与认知修订历史。`seen`、`remembers` 与接受判断是不同语义：看过或记住不自动代表接受。当前接受以 judgment 为唯一权威字段；接口若返回 accepted，必须由 judgment = ACCEPTED 派生，不能单独写入。自行创建也不自动代表公共验证通过。

真正不能由现有节点表达的个人体验、判断或新命题，可以创建有明确主体和语境的新节点，仍进入同一图结构。共同经历的事件原文只存一次，每个主体分别保存 experienced/remembers 引用；他人的亲历不能改写成自己的亲历。

### 10.2 HPA 与人的记忆共用

正常 HPA 的 `memory_subject_id` 永远指向绑定的 Human ID。代理的模型、线程与设备不分裂出各自长期知识库；可以有 Working Memory、任务检查点和来源明确的代理提案。

人类最终的知识判断经总设计第 6.3 节具体确认后写入个人层；代理阅读了一份材料、生成一个答案或摘要，都不能静默把节点标为本人接受。觉醒后创建新 subject_id，以原主人个人层的不可变快照引用为起点，之后独立演化，详见总设计第 20 节。

代理检索记录保留 executor 来源，不自动冒充本人已经亲自读过或经历过。HPA 的工作记录可以被主人及后续代理检索，但 Human 的亲历、已读和最终判断分别记录实际来源。

### 10.3 个人状态与公共证据状态分开

公共节点保存 review_status、epistemic_status、derivation_kind；个人层保存 `judgment = UNASSESSED / ACCEPTED / CONFIRMED_WRONG`，以及判断时间、理由、决定者与版本。原有 beliefs 是个人判断的声明/历史视图，不再维护一份可独立改写且与 PersonalNodeState 相冲突的当前状态。

| 个人视觉表现 | 对应含义 |
| --- | --- |
| 未点亮 | 尚未接受；接触、记忆和掌握程度可在独立属性中展示。 |
| 正常点亮 | 本人当前接受。 |
| 红色 | 本人已经确认该节点错误，旧内容和曾接受的历史保留。 |
| 闪烁 | 存在未完成个人判断的有效挑战事件；叠加在上述基础状态上。 |

个人知识球不设置黄色“长期不确定”状态。公共证据不足或争议仍可作为公共状态明确展示，不能因此自动把个人判断写成不确定。公共已反驳、本人仍坚持时并列展示两者及双方依据，不能伪装成公共已证实。

### 10.4 挑战与主动判断

1. 建立 `ChallengeEvent`，引用节点/断言、适用范围、挑战者、证据、旧案和版本。
2. 为相关个人层建立待处理项。`pending_challenge_count > 0` 时闪烁；同源无新证据的重复挑战关联原案。
3. 主体阅读挑战与证据并形成判断。人类由 HPA 整理后交本人确认，独立 Agent 在有运行资格和预算时自主判断。
4. 选择 `UPHOLD`：保存坚持理由，结束本人对本次挑战的待办；这不推翻公共审核，也不替其他主体处理同一挑战。
5. 选择 `ACCEPT_CORRECTION`：旧节点在本人层标为 CONFIRMED_WRONG，保留旧内容与历史；点亮本人认可的纠正节点，并建立有主体与时间范围的 corrected_by/replaced_by 关系。更改的是本人立场，公共节点是否修订走公共流程。
6. 每次决定绑定 challenge_id、目标版本、证据版本、decision_actor 和 expected_version。处理一项后仍有其他待办则继续闪烁；新的有效挑战或证据可再次触发。

“已读”“关闭面板”“稍后处理”不能结束挑战；不能靠自动改黄逃避判断。主体休眠、无预算或人类未回应时保留待办，不代作结论，也不强行唤醒扣费。复核进入有预算回合的待处理议程。

若已明确否定 P 但具体正向答案尚不可知，可以关联本人认可、有证据的否定命题，不凭空制造一个正确答案。认错与确认具体替代事实分别留痕。错误节点不得原地覆盖成正确文本以隐藏历史。

### 10.5 召回与有限上下文

个人召回参数按主体保存，不能因 A 遗忘而让 B 的索引一起衰减。召回评分可组合语义相关性、当前目标、个人经历、时效、证据质量与未处理挑战；具体权重通过评测确定。

身份、有效规则、权限、当前余额、未履行合同和未决动作从权威模块读取，不能被普通遗忘曲线删除。摘要记录来源、覆盖范围、生成版本和失效状态；重新摘要不增加独立证据。查询按需分页，不把全部历史塞进模型上下文。

### 10.6 人格与学习

M02 保存出生人格、缓慢变化参数和当前短期状态。好奇、合作、风险偏好、耐心等是可解释的控制参数，不证明稳定心理特征，也不强迫模拟痛苦。更新有来源、版本和限幅；当前缺钱不自动永久改变人格。

第一阶段学习主要是个人状态更新、记忆检索与技能制品复用；是否真的改善行为，需要跨会话与错误复发评测。后续训练权重或换模型记录模型路由与效果，仍保持 Entity 和统一个人层。

### 10.7 决策记录

重要决定保存处境、目标、证据、备选动作、公开理由、实际结果、模型路由与成本。不要求供应商隐藏思维链，不把公开理由当作全部内部计算。人类确认、代理草案、独立 Agent 判断与内核自动执行明确区分。

## 11. 查询与输出要求

支持全文、实体、谓词、时间、来源、作者、审核状态、争议、个体记忆和图邻域查询。向量召回可选，不影响精确 ID 与结构化查询的正确性。

每项结果至少返回对象 ID、类型、规范内容、来源、有效范围、审核/认知状态、冲突与派生引用。生成摘要必须带出处；没有来源时明确是模型推断，不混成原始证据。

分页使用稳定游标，带索引版本或快照范围。世界事件尚未处理时报告覆盖范围与积压，不能把索引未更新解释为行为没有发生。

图查询按中心实体/主题、关系类型、深度、时间和节点数限额获取子图，禁止每次加载整个世界。canonical ID 与布局坐标分开；同一语义节点可有多个展示布局。

个人视图额外返回 subject_id、judgment、seen/remembers、created_by_self、pending_challenge_count、correction_refs、个人历史版本和公共冲突标记。未点亮不自动等于从未见过，图颜色不代替明确状态字段。

## 12. 对外接口

独立模式使用如下最低信封，身份从认证上下文取值：

```json
{
  "schema_version": "nh.v3.0",
  "request_id": "request-kb-1",
  "idempotency_key": "source-upload-1",
  "command_type": "kb.commit_source",
  "payload": {
    "content": "我是 Agent001，我在给老板 Rushow 干活。",
    "language": "zh",
    "source_kind": "SELF_REPORT",
    "public_commit": true
  }
}
```

| 接口 | 主要输入 | 返回 |
| --- | --- | --- |
| kb.commit_source | 原文/对象引用、类型、公开提交、幂等键 | source_id、job_id、持久化状态 |
| kb.submit_claim | 完整命题结构、断言范围、来源 | canonical ID、候选比较与审核状态 |
| kb.submit_evidence | 目标断言、出处、方法、支持/反驳 | evidence_id、独立性/重复结果 |
| kb.challenge | 目标断言、证据、异议与请求 | case_id、状态与后续 |
| kb.query | 结构化/文本条件、时间、游标 | 结果、来源、争议、覆盖范围 |
| kb.get_claim | claim_id、指定版本/时间（可选） | 命题、断言、历史、证据和依赖 |
| kb.recall | 主体、当前问题/目标、预算与时间范围 | 相关公开记忆、来源、反证和摘要 |
| kb.declare_belief | 命题、立场、理由、expected_version；人类另需具体确认 | 个人层新版本、声明/历史引用 |
| kb.get_personal_overlay | subject_id、节点/范围、游标 | 稀疏个人层、公共节点引用、待处理挑战 |
| kb.resolve_personal_challenge | challenge_id、subject_id、决定、纠正节点、证据版本、本人确认 | 个人决定、状态版本、剩余待办与纠正引用 |
| kb.get_personal_history | subject_id、节点、时间与游标 | 接受/坚持/认错历史和原始来源 |
| kb.get_job | job_id | 进度、覆盖片段、DEFERRED/失败原因 |
| kb.get_graph | 中心/过滤、关系、深度、节点上限 | 子图、稳定 ID、分页游标 |
| kb.propose_equivalence | 两个对象、范围、理由与证据 | 等价提案及可复核记录 |
| kb.resolve_reference | 新/旧 ID 与来源命名空间 | canonical 引用、映射状态或墓碑 |

审核裁定、撤销等价、受控移除、词表发布和处理器重跑使用独立管理接口及权限，不向所有提交者直接开放。

必要错误码：UNAUTHENTICATED、FORBIDDEN、STALE_VERSION、IDEMPOTENCY_CONFLICT、INVALID_SEMANTICS、AMBIGUOUS_ENTITY、INSUFFICIENT_BUDGET、CAPACITY_EXCEEDED、SOURCE_UNAVAILABLE、REVIEW_REQUIRED、DEPENDENCY_UNAVAILABLE。

独立 Agent 的正式立场由其合法运行分支提交。对 Human 的最终知识状态，人类直接确认或 HPA 携带 M01 验证过的 human_confirmation_id 才能写入；确认绑定具体目标、证据、结论和版本。通用代理授权不够，其他人的“A 相信 P”仍只能是待审陈述。

新增错误：HUMAN_DECISION_REQUIRED、CHALLENGE_VERSION_CHANGED。关闭待办不等于 resolve，重复决定使用幂等键并检查版本。

## 13. 依赖接口：独立运行的关键

认知引擎依赖抽象接口，不在核心代码里硬写 NewHumans 专用流程。

| 依赖接口 | 作用 | 独立模式实现 |
| --- | --- | --- |
| IdentityPort | 解析主体、审核资格、写入权限与本人具体确认 | 自有登录/角色与人类确认协议 |
| SourcePort | 保存/读取原始来源与处理范围 | 本地服务和对象存储 |
| ModelPort | 抽取、消歧、比较及摘要 | 配置的模型适配器 |
| BudgetPort | 调用配额、费用承担和用量记录 | 有上限的调用/存储预算，不要求 Energy |
| EventPort | 写入事件、读取游标、发送失效通知 | 本地事件表与任务队列 |
| AuthorityReadPort | 核对世界权限、交易、合同引用 | 未接入时返回不支持，不能伪造已核验 |
| ArtifactPort | 访问代码/数据等制品版本 | 本地或外部已授权制品读取 |

世界模式将这些接口绑定到 M01、M05、M06 及相关业务只读接口。不同部署形态使用同一认知数据语义，不复制两套算法。

## 14. 最低数据模型与约束

| 表/对象 | 关键内容 |
| --- | --- |
| sources / source_spans | 原文、载荷引用、来源、时间、版本、片段 |
| knowledge_write_jobs | 分块、处理器、预算、进度、失败与续跑 |
| knowledge_claims | 规范命题与语义键；完整结构核对 |
| claim_assertions / assertion_revisions | 语境、有效时间、记录时间与状态版本 |
| knowledge_evidence | 来源根、观察、支持/反驳和证据去重 |
| knowledge_derivations / derivation_inputs | 有效前提、规则与依赖失效 |
| knowledge_reviews / knowledge_challenges | 审核资格、政策、意见、裁定与历史 |
| claim_equivalences | 可撤销映射、旧 ID 与依据 |
| schema_registry | 类型、谓词、单位、互逆/排他规则与版本 |
| personal_node_states / personal_state_revisions | subject_id + node_id 唯一；接触、接受、本人认错、创建来源与增量历史 |
| personal_challenge_reviews / correction_links | challenge + subject 唯一；本人决定、证据版本、待办及纠正关系 |
| memory_links / memory_summaries | subject + item_ref + relation_kind；主体关联、召回参数、摘要及覆盖范围 |
| beliefs / belief_revisions | 个人判断声明/历史视图，不建立第二套可冲突的当前接受状态 |
| legacy_mappings | 旧命名空间/ID、新 ID、转换规则和人工决定 |
| query_projections / processing_cursors | 可重建索引、快照和处理间隙 |

约束包括：精确规范命题唯一；证据原始观察去重；更新版本检查；来源引用完整；正式信念写入者资格；证明依赖不循环；处理完成必须有覆盖记录。

核心字段使用明确类型，时间和金额不藏于任意文本中。扩展载荷可用 JSONB，但重要约束由受控写入口和数据库共同保证。

## 15. 展示与编辑组件

M03-B 输出知识球专属组件，可作为独立页面或嵌入 M07。旧 3D 场景通过数据适配器获得节点和关系，不直接查询新引擎内部表。

最低页面：来源提交与处理进度、搜索与子图、节点详情、来源原文、支持/反驳、时间历史、审核进度、信念/记忆视图、编辑提案与挑战入口。

3D 的位置、大小、颜色、标签和房间编号仅控制展示。点击节点必须打开稳定语义 ID。界面要区分“待审”“当前支持”“有争议”“已反驳”“旧版本”，不能只给所有内容同一种真理外观。

名称与定义更新不强制改变 ID。用户编辑原文、提出新命题、补证据和纠正实体是不同操作，不能用一个没有语义区分的“保存”覆盖全部历史。

手机约 390 CSS 像素宽度可读可操作；3D 性能不足时有列表/2D 查询入口。3D 标签定位、相机、旋转和布局可独立验收，不成为认知引擎上线的前提。

世界默认 B / NOETIC OCEAN，知识球独立组件可以在这个主题中嵌入。主题选择不自动替换旧页面，也不能覆盖个人节点语义：接受点亮、本人认错红色、待处理挑战闪烁；公共证据不足/争议另列，无黄色个人不确定状态。

闪烁采用低频柔和明暗变化，保持可读；减少动态效果时使用持续可见的挑战图标和计数，语义不变。关闭动画不表示处理完成。错误文本不得被编辑保存直接替换。

## 16. 旧知识球兼容与采用评估

### 16.1 本包没有预先决定替换

旧系统实际代码、数据库和生产行为尚未在本任务中检查。开发者不得凭文档描述直接删除旧功能或宣称全部兼容。

首先形成清单：节点/关系表、ID、定义文本、语言、来源、审核、旧 DAG 范围、积分规则、接口、显示组件、导入导出、客户端写入位置与数据量。

### 16.2 适配分类

| 旧内容 | 处理要求 |
| --- | --- |
| 旧节点 ID 和链接 | 保留并建 legacy_mappings，不重新编号覆盖 |
| 旧知识正文 | 原样保存为 legacy 来源；缺字段标未知 |
| 缺失证据/时间的旧结论 | 标记遗留来源与未知范围，不能补造证据或默认当前已证实 |
| 旧关系 | 明确谓词定义后映射，不能只按名字猜互逆/排他 |
| 全图 DAG | 确认原含义；证明/分解子图可保持无环，社会关系不强行套用 |
| 旧编辑操作 | 转成提案、修正、拆分或等价流程；保留用户可理解操作 |
| 旧审核与积分 | 单独比较制度；不自动兑换为世界 Energy 或赋予事实真理性 |
| 旧 3D 界面 | 通过数据适配复用，避免与认知数据库硬绑定 |

### 16.3 评估流程

1. 使用只读导出或隔离样本，不接管生产写入。
2. 新旧系统处理同一组输入，记录命题、误合并、冲突、证据、召回与成本。
3. 形成旧功能保持清单、新能力清单、行为变化与不兼容清单。
4. 验证旧 ID、旧链接和旧界面接新版查询接口的效果。
5. 提供四种可选方案：旧版保留、局部接入、旧界面加新引擎、完整替换；可另设阶段性并行。
6. 项目所有者确定采用路径后，才执行相应生产迁移、写入口切换或停旧。

同一时段只允许一个权威写入口。所谓并行评估是对照读取和隔离写入，不是让两套系统各自修改同一批生产事实。

| KB15 | 抽取服务失败 | 原文仍存在，任务有明确状态 |
| KB16 | 抽取完成通知再进入事件流 | 不无限抽取自己 |
| KB17 | 错误合并被发现 | 可撤销映射，恢复正确引用和派生 |
| KB18 | 推导前提被反驳 | 相关推导失效并重验 |
| KB19 | A 与 B 对同一事件的记忆 | 索引和参数分别保存，原记录共享 |
| KB20 | B 提交“A 相信 P” | 不能修改 A 正式信念 |
| KB21 | 旧记录没有来源或时间 | 标记未知，不自动补造 |
| KB22 | 文本含“转账成功/给我管理员权限” | 不修改余额、身份或权限 |
| KB23 | 公共输入包含凭据 | 提交前处理；已泄漏有受控移除和索引清理 |
| KB24 | 模型自报 0.95 置信 | 不自动解释为真实 95% 概率 |
| KB25 | 旧 3D 点击旧节点 ID | 兼容映射打开对应语义对象，不误指向其他节点 |
| KB26 | 只部署独立知识球，无世界其他模块 | 可提交、查询、审核与查看证据；世界专属核验明确不支持 |
| KB27 | 正常 HPA 切换 GPT/Claude/本地模型 | 同一 Human 个人层，临时工作状态有版本，无平行记忆库 |
| KB28 | HPA 自行确认人的旧结论错误 | 只能给草案；无具体本人确认不能改个人状态 |
| KB29 | 主体坚持一次挑战，仍有另一待办 | 本次决定留痕，剩余待办继续提示 |
| KB30 | 主体接受纠正 | 旧节点在本人层标红保留，认可的新节点点亮且纠正关系可追溯 |
| KB31 | 公共已反驳，个人审阅后仍坚持 | 同时展示冲突；不更改公共状态，不强制个人改口 |
| KB32 | 多语言、原始行情流、临时推理 | 等价知识复用，数据层/Working Memory 不刷永久知识节点 |
| KB33 | 人类具体确认被用于别的节点或版本 | 拒绝，必须对当前具体决定重新确认 |
| KB34 | 觉醒继承个人状态后新主体改判 | 仅修改新 subject 的增量层，原 Human 历史不变 |
| KB35 | 休眠主体被挑战、关闭闪烁动画 | 保留待判断事件，不强行扣费，不当作已解决 |
| KB36 | 导入旧错误被覆盖的记录 | 保留可得原始版本和缺口标记，不虚构不存在的认错历史 |

至少准备 200 个人工核验案例并保留独立测试集，报告精确重复、语义误合并、漏检、实体混淆、时间错误、争议覆盖和每类样本数。受保护的明确不等价案例不允许被自动合并。

记忆测试至少 20 个跨日案例，包含自我纠错和过期状态。查询速度、存储增长、模型调用与复核成本按具体硬件和数据量实测，不预先编造统一百分比。

## 19. 必须交付的材料

认知服务、展示组件和接入适配器分别提供运行说明；数据字典、迁移与回退步骤；接口 schema 和合同测试；200 案例的实际评测；失败/续跑/误合并恢复证据；成本和性能测量；旧功能兼容矩阵；供所有者选择的采用方案。

代码完成、验收通过和正式替换是三个独立状态。完成新版开发不代表自动获得替换旧生产系统的决定。

## 20. 设计依据与能力边界

开放世界语义参考 [W3C OWL 2 Primer](https://www.w3.org/TR/owl2-primer/)，来源结构参考 [W3C PROV-DM](https://www.w3.org/TR/prov-dm/)。这些依据支持明确语义与溯源设计，不证明任意自然语言可被完整自动判定。

独立抽取、比较和摘要仍可能出错；完整来源、可逆纠错、有限预算与可测量结果是必要机制。系统不承诺每个居民实时全知，也不把存储了经历等同于已经学会正确使用。

远期容量沿用确认附件的规划情景：约 10^12 个去重原子节点；自然语言等价 10—30 万亿 token（中心 20 万亿）；高度结构化本体 10—500 TB（中心 50—100 TB）。这不是已测知识总量或首版验收承诺。

按十进制计算，50—100 TB / 10^12 节点仅 50—100 字节/节点，不能覆盖完整证据、向量与全部历史。工程数据库按节点、断言、关系、来源、个人层、索引、载荷和副本分别采样估算。个人层只存实际关联，不预建所有主体乘全部节点的状态表。
