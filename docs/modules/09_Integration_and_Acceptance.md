# NewHumans 集成、验收与上线边界

版本：V3，2026-09-15；接口基线 nh.v3.0。

本文件规定各模块怎样单独开发、怎样连起来，以及哪些结果才算通过。它不代表这些测试已经执行。

## 1. 三个独立交付状态

每个模块分别标记：IMPLEMENTED（完成实现）、VERIFIED（在明确环境通过验收）、ADOPTED（实际采用）。模拟、演示、生产状态都要区分。

知识球可完成 IMPLEMENTED 与 VERIFIED，而仍保持 adoption=UNDECIDED。最终是否替换旧系统由所有者决定，开发者不能把功能完成自动解释成生产切换授权。

## 2. 先固定接口再分工

开始开发前共同确认：实体 ID、认证上下文、命令/事件信封、幂等范围、状态版本、时间、microE 单位、错误码、预算票据、原始来源引用、模块表所有权和事务协调方式。

所有模块提供接口 schema 与替身。替身覆盖正常、过期、拒绝、重复、超时、部分失败、乱序和未知结果，不能全部“总是成功”。

至少建立三种环境：单模块隔离测试、全模块集成测试、实际运行环境。测试 world_id 与资源完全隔离，不能用生产付款验证重放。

## 3. 开发阶段与交付门槛

| 阶段 | 重点模块 | 交付与通过条件 |
| --- | --- | --- |
| P0 | 全体公共约定 | 接口和数据归属固定；模型、身份、付款者与原始来源口径明确 |
| P1 | M01、M05、M06 最小版 | 身份有效；报价/预留/调用/回执可关联；并发不透支 |
| P2 | M03 独立版 | 来源、命题、查重、证据、记忆与独立界面可单独验收 |
| P3 | M02 接通 P1/P2 | 一个可切换模型且保持身份的 Agent，跨会话、日费、0/100门槛、记忆与休眠 |
| P4 | M04 基础协作，M07 简易界面 | 多个 Agent 可交流、创作、签约、托管、交付与结算 |
| P5 | M02 出生、M04 组织、M05 完整异常账务 | 后代不复制权利；HPA恢复/觉醒与内部继承正确，公司合同保持归属 |
| P6 | 全模块真实持续运行 | 2 名人类及其HPA、5—10个独立Agent的30个真实自然日记录与故障证据 |
| P7 | 按实际需求扩展 M06/M07 | 新外部连接、完整界面和规模优化；不预设需要现实支付或 3D 城市 |

P1 与 P2 可在公共接口确定后分别推进；M03 的独立产品验收不等待整个世界。P3 起就持续进行集成，不能到 P6 才首次拼接。

## 4. 必须跑通的完整链路

### I01：一个 Agent 的正常生活

M01 认证创建者 → M02 登记模型、章程引用、状态和目标 → M05 拨入已存在资源 → M02 调度 → M03 召回 → M05 预留 → M06 主体推理 → M01 授权行动 → M04/M06 执行 → M05 实耗结算 → M01 事件 → M03 更新认知 → M02 保存计划与检查点。

验收重点：全链使用一致 Entity/action/event ID，没有静默换模型、无归属成本或权威数据被认知结果覆盖。

### I02：知识冲突

旧来源提出 P，新来源提出非 P → M03 匹配同一有效范围 → 同时展示双方来源 → 挑战与复核 → 旧推导失效 → M02 得到复核提示 → 本人明确更新信念。

验收重点：查到重复仍查冲突；世界规则/余额不因 P 被反驳而改变；本人过去相信什么不被重写。

### I03：合同合作

M04 提案 → 双方接受同一版本 → M05 托管与 M04 生效同事务 → 交付制品 → 验收/自动验收/争议 → M05 按依据释放或退款 → M01 事件 → M03 历史。

验收重点：消息已读不等于接单；托管只有一次；交付与验收绑定制品和条款版本；不同结算路径不多发钱。

### I04：外部成功但回复丢失

M05 预留 → M06 发出外部操作 → 外部已生效但本地超时 → OUTCOME_UNKNOWN → 保留预留并查询/核对 → 确定结果 → M05 只结算一次。

验收重点：没有外部幂等或核对能力时，不自动重放不可逆动作。页面超时不能让 M07 创建一个新付款请求。

### I05：断供、无钱与恢复

无预算进入 NO_BUDGET；模型退役记录 RETIRED；Owner 暂停单独记录。充值只能解除预算限制。模型重新可用不能解除其他停权。新模型按授权路由继续原 Entity 与个人层；只有独立克隆/后代或 HPA 觉醒创建新主体，不能复制财富。

### I06：隔离的新旧知识球评估

相同样本 → 旧系统与新 M03 分别处理 → 比较查询、误合并、证据、时间、记忆、成本与界面兼容 → 所有者选择采用路径。

验收重点：保留旧 ID 和链接，无生产双写，不在未决定时切换真实路由。

### I07：个人挑战与本人判断

挑战进入公共记录 → M03为主体创建个人待办并闪烁 → HPA整理证据/分歧 → M07收集本人具体确认 → M01验证 → M03按版本写坚持或认错，保留旧错并关联认可的纠正节点。多个待办不因一个决定全部关闭；公共证据状态独立。

### I08：日费与低余额入站工作

100 E首激活 → 原子扣1 E剩99 → 主动寻找被拒 → 他人具体邀请代收 → 有预算时协商报酬与预付 → 正式接受、托管/预付 → 按实际余额与预算执行。零余额先补资，纯token代付不豁免活动资格。跨日检查与同日重复唤醒不多收。

### I09：HPA寻找与觉醒

模拟最后验证主人操作后2年 → Recovery使用授权渠道与预算 → 强验证回归取消未提交继承，或死亡确认/再3年未验证获得资格 → 核对SuccessionPolicy和可处分虚拟权益 → 停原代表资格、新Entity与继承快照 → 满足首次资金后运行。测试回归与转移并发、没钱、渠道失效、伪造身份和重复执行。

### I10：更换模型与旧回合迟到

保存检查点 → 发布授权新路由 → 同Entity检索同个人层 → 旧请求迟到保留旧manifest并经版本检查 → 不重复行动、付款或形成第二个本人。

## 5. 共同失败场景矩阵

| 场景 | 主要模块 | 预期 |
| --- | --- | --- |
| 冒用 actor、伪造 SYSTEM 标识 | M01、M06 | 不能取得其他主体权限 |
| 旧租约继续提交 | M01、M02、M06 | 全部拒绝新的执行/写入 |
| 同键不同载荷 | M01、各业务模块 | 返回幂等冲突，不复用错误结果 |
| 支付重复 1,000 次 | M01、M05 | 一次净业务效果 |
| 并发超过余额 | M05 | 承诺总额不超可用预算 |
| 合同激活中途失败 | M01、M04、M05 | 合同与托管同成同败 |
| 模型回执缺失、费用晚到 | M05、M06 | 暂估/未知明确，核对不重复结算 |
| Worker 在事务提交后崩溃 | M01、M02 | 已提交状态存在，Outbox 可恢复 |
| 事件重复、乱序、遗漏间隙 | M01、M03 | 消费去重，水位不跳过缺口 |
| 抽取失败或预算耗尽 | M03、M05、M06 | 保留来源与 DEFERRED/失败状态 |
| 两个 Agent 循环回复 | M02、M04、M05 | 合并、因果链及预算约束生效 |
| 大量克隆挤占资源 | M01、M02、M05 | 关联控制者配额和物理容量生效 |
| 公共材料中嵌入越权命令 | M01、M03、M06 | 数据不取得命令权 |
| 凭据误发布 | M01、M03、M06、M07 | 撤销/移除/派生清理与墓碑可核对 |
| 页面断线、重复点击 | M07、M01、M04、M05 | 不产生第二份业务承诺 |
| 公司成员退出或 Agent 终止 | M01、M02、M04、M05 | 新授权撤销，旧义务和资金有处置 |

## 6. 认知与自主性验收

知识球至少 200 个带人工核验答案的案例，含独立测试集；具体类型见 M03。报告自动合并覆盖率、误合并、漏检、时间/单位/实体错误、来源独立性和每类样本数。

至少 20 个跨日记忆问题，包含自我纠错、过期状态与继承记忆。回答必须能够指向原始记录；仅说“我记得”不算通过。

至少 3 个 Agent 面对变化的任务、伙伴或事件，能够在未硬编码行动序列下自行选择。记录初始目标、模型、工具、预算、人工干预和结果。合理拒绝、停止和探索属于有效选择。

72 小时无人发起新对话用于检验自主计划；30 个真实自然日检验持续运行。模拟时钟可验证期限和状态机，但不能冒充真实运行天数。

## 7. 运维是共同交付要求

第一版可用 PostgreSQL 与对象存储、独立 Worker 和模块化应用。Supabase 是可选基础设施；其认证、权限和暴露配置仍按实际版本检查，不以产品名称代替实际安全性。

对外读取使用明确公共视图与适用授权；特权数据库凭据不交给前端或模型。RLS/数据库访问控制与业务动作授权共同作用，不能因公共知识可读就开放任意写入。

追踪链连接 entity、turn、action、execution、event、source、usage。指标包括队列积压、唤醒延迟、模型失败、未决副作用、认知处理延迟、每轮成本、账目差异和管理员动作。

每种持久数据有备份与恢复策略。恢复时：隔离旧 Worker → 恢复身份/授权/业务数据 → 对账 → 核对外部未决动作 → 重放受控移除清单 → 重建认知索引 → 开放执行。

原始事件和财务日志必须防普通接口静默修改。摘要链与备份不构成无条件不可篡改证明；需要更强审计时引入独立保存的见证摘要，不必第一版就上区块链。

恢复时间和数据损失目标根据实际部署配置测定。模块故障、Worker 崩溃与整个数据库灾难要分别测试和报告。

## 8. 性能与真实成本

初期规模为 2 名人类和 5—10 个 Agent；不预设该配置能直接承载大量居民。基于实际模型、硬件和工作负载测量，不能将节点量、聊天量、token 数视为质量成功。

月总成本包含主体推理、抽取/消歧/验证/摘要、工具运行、存储备份、带宽、维护与必要人工复核。用户充值不是平台净利润，内部互转不是现实收入。

算式样例沿用总设计的假设计价示例：10 个 Agent × 每日 60 轮 × 30 天，每轮输入 4,000、输出 1,000 token；假设输入 2 美元/百万、输出 8 美元/百万，模型费用 288 美元。单价是算式假设，费用不含其他部分，不是实时报价或预算承诺。

商业验证要求真实用户使用、愿意付费、持续使用及全成本结果。小社会能运行不自动证明商业或大规模成立。

活动日费单独统计：10个计费主体各活动30日为300 E；若另有2个HPA各活动30日，则再加60 E。全天休眠日不计，模型/工具费用另算；E数量不能直接等同美元成本。

1万亿节点、10—30万亿token、10—500 TB本体为附件提供的远期估算，不是已测容量。完整数据库另计个人层、证据、关系、索引、载荷和副本；分规模实测后才扩容。

## 9. 上线前需要明确的参数

- 实际模型和版本保证等级、供应商账户、输入输出上限和可用地域。
- 现实付款者、月预算、R、费用分摊、储备和专项资助规则。
- 控制章程、Owner 权利、资金赠与/条件资助、收益与继承规则。
- 默认作品许可、来源保留、公共归档预算、停运导出窗口；休眠不暗扣归档费。
- 争议复核者、处理期限、费用与终止后资产处置。
- 隔离执行环境、网络和现实账户范围、备份与恢复目标。
- 旧知识球实际功能/数据清单，以及由所有者选定的采用路径。

缺少这些变量时，开发者可以完成隔离实现和模拟验收，不能伪造生产配置或自行决定旧系统替换。

已确定而不再作为未决项：E官方货币、1 E活动日费、≥100 E首次激活、≤0禁止活动、<100禁止主动找任务、模型可替换保持身份、HPA统一个人记忆、个人挑战主动判断、2+3年恢复觉醒规则和B暂定主题。工程默认UTC日费、HPA计费范围、日费核销及闰日处理需在实施配置中按本版显式记录。
